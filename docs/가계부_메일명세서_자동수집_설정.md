# 가계부 — 카드사 메일 명세서 자동 수집 설정

카드사가 매달 보내는 **e-메일 이용대금명세서**를 받은편지함에서 직접 걷어, 지금 쓰는
가계부 파서에 그대로 태우는 기능이다. 코드는 이미 들어가 있고(`c64befc`), **기본은
꺼져 있다.** 이 문서대로 `backend/.env` 만 채우면 켜진다.

작성 2026-08-20 · 코드 기준 `backend/src/app/data/market/budget/mailbox.py`

---

## 1. 왜 메일인가 — 다른 길은 다 막혀 있다

자동으로 카드 내역을 받아 올 방법을 전부 확인한 결과다.

| 방법 | 가능? | 이유 |
|---|---|---|
| 마이데이터 API | 불가 | 금융위 허가받은 사업자만 호출. 개인은 신청 자체가 안 됨 |
| 오픈뱅킹(금융결제원) | 불가 | 이용기관 등록이 법인 기준, 카드 이용내역은 범위도 제한적 |
| 카드사 개발자 포털 | 불가 | 신한 Open API·우리카드 포털 모두 제휴사용. 삼성·롯데·하나는 창구 없음 |
| CODEF 스크래핑 API | 가능하나 보류 | 개인 데모(3개월·일 100회) 있음. 정식 요금 비공개, 인증수단 위탁 필요 |
| 승인문자(SMS) 파싱 | 부적합 | **할부 회차·부분취소·청구월을 못 잡음.** 이 가계부는 청구월이 뼈대라 못 씀 |
| **e-메일 명세서** | **채택** | 월 1회지만 청구월·할부가 확정된 원본. 자격증명이 **메일 계정 하나뿐** |

메일 방식의 핵심 장점은 **카드사 로그인 정보를 어디에도 맡기지 않는다**는 것이다.

---

## 2. 준비 — 카드사에서 이메일 명세서 신청

각 카드사 앱/홈페이지에서 명세서 수신 방법을 **이메일**로 바꾼다. 메뉴 이름은
카드사마다 다르다(“명세서 수신방법”, “이용대금명세서 관리”, “e-메일 명세서 신청” 등).
결제 계정 메일과 아래 IMAP 계정이 **같은 주소**여야 한다.

현재 전용 파서가 있는 곳은 **신한·롯데·하나·삼성** 네 곳이다. 나머지 카드사도
수집·파싱은 되지만 추정 파싱이라 전부 대기함으로 간다(§5 참고).

> 첫 명세서는 신청한 다음 결제월부터 온다. 그 전까지는 수집기가 돌아도 걷을 게 없다.

---

## 3. 메일 계정에서 IMAP 켜기

메일함을 읽으려면 계정 쪽에서 IMAP 을 먼저 허용해야 한다.

| 메일 | 서버 / 포트 | 먼저 할 일 |
|---|---|---|
| 네이버 | `imap.naver.com` / 993 | 메일 → 환경설정 → **POP3/IMAP 설정** → IMAP/SMTP 사용 **켜기** |
| 지메일 | `imap.gmail.com` / 993 | 2단계 인증 후 **앱 비밀번호**(16자리) 발급. 계정 비밀번호로는 안 됨 |
| 다음 | `imap.daum.net` / 993 | 메일 환경설정에서 IMAP 사용 허용 |

## 4. `backend/.env` 채우기

```
# 카드사 메일 명세서 자동 수집
BUDGET_MAIL=true
IMAP_HOST=imap.naver.com
IMAP_PORT=993
IMAP_USER=molba06@naver.com
IMAP_PASSWORD=메일_비밀번호
IMAP_FOLDER=INBOX

# 어느 계정의 가계부로 넣을지 (스케줄러는 로그인 세션이 없어 물어볼 데가 없다)
BUDGET_MAIL_USER=admin

# 첨부 파일 비밀번호 후보 — 명세서는 보통 생년월일 6자리 등으로 잠겨 온다.
# 쉼표로 여러 개 나열하면 앞에서부터 시도한다.
BUDGET_MAIL_PASSWORDS=900326,0326
```

선택 설정(안 넣으면 기본값):

| 키 | 기본 | 뜻 |
|---|---|---|
| `BUDGET_MAIL_DAYS` | 45 | 받은편지함을 며칠치까지 훑을지 |
| `BUDGET_MAIL_MAX` | 40 | 한 번에 살펴볼 최대 메일 수 |
| `BUDGET_MAIL_CHECK_INTERVAL` | 1800 | 자동 확인 주기(초). 명세서는 월 1회라 30분이면 충분 |
| `BUDGET_MAIL_AUTOIMPORT` | true | false 로 두면 **전부** 대기함에 쌓이고 사람이 눌러야 등록 |

`.env` 는 git 에 올라가지 않는다(`.env.example` 만 커밋됨). 설정 예시는
`backend/.env.example` 아래쪽에도 같은 내용이 주석으로 들어 있다.

## 5. 켜고 확인하기

```powershell
.\ops\win\serve.ps1 restart -App backend
```

그다음 **가계부 탭 → 왼쪽 "메일 명세서 자동 수집"** 패널을 본다.

1. 안내 박스가 사라지고 계정·폴더·주기가 한 줄로 뜨면 연결된 것이다.
2. **"지금 확인"** 을 누르면 스케줄러를 기다리지 않고 즉시 훑는다.
3. 결과가 그 자리에 문장으로 뜬다 — 예: `신한카드 2026-09 42건 등록`,
   `롯데카드 2026-09 31건 — 확인 대기(청구월 미확정)`.

스케줄러 상태만 따로 보려면:

```powershell
(Invoke-WebRequest "http://127.0.0.1:8000/api/ops/stats" -UseBasicParsing).Content |
  ConvertFrom-Json | ForEach-Object { $_.schedulers } |
  Where-Object { $_.name -eq 'budget_mail' } | ConvertTo-Json -Depth 4
```

### 자동 등록 vs 대기함

**전용 파서로 읽혔고 + 청구월이 확정됐고 + 카드 설정과 충돌이 없을 때만** 바로 들어간다.
하나라도 어긋나면 대기함에 서고, 화면에 왜 세웠는지 적힌다.

| 대기 사유 | 무슨 뜻인가 | 어떻게 할까 |
|---|---|---|
| 전용 파서가 아닌 추정 파싱 | 신한·롯데·하나·삼성 외 카드사이거나 PDF 명세서 | 내역 보기로 금액 확인 후 등록 |
| 청구월 미확정 | 파일에 청구월이 없어 '마지막 거래월 +1' 로 추정 | 카드 결제일 설정을 넣으면 자동 계산됨 |
| 카드 설정과 청구월 불일치 | 명세서가 말한 달과 내 설정이 다름 | 둘 중 하나가 틀린 것 — 결제일 설정부터 확인 |
| 거래를 찾지 못함 | 명세서가 아니거나 형식이 낯섦 | 버리거나, 원본을 보고 파서 보강 |

좁게 잡은 이유는 카드사마다 '금액' 의 뜻이 달라서다(할부 원금이냐 총액이냐, 수수료
포함이냐). 잘못 들어간 값은 몇 달 뒤 합계가 안 맞을 때야 드러나고, 그때는 어느
명세서가 범인인지 찾기 어렵다.

## 6. 문제 해결

| 증상 | 원인 / 조치 |
|---|---|
| "받은편지함을 열지 못했습니다" | IMAP 미허용이거나 비밀번호 오류. 지메일은 **앱 비밀번호**여야 함 |
| 메일은 있는데 0건 | 제목·보낸사람 판별에서 걸러짐. `POST /api/data/budget/mail/scan?rescan=true` 로 재판정 |
| 이력에 "암호 필요" | `BUDGET_MAIL_PASSWORDS` 후보에 실제 비밀번호가 없음. 후보 추가 후 `rescan=true` |
| 같은 명세서가 또 들어옴 | 안 들어온다. 거래 지문(`fp`)으로 중복을 거른다 |
| 메일이 읽음 처리됨 | 이 기능 때문은 아니다. IMAP 을 `readonly` 로 연다 |
| 스케줄러가 안 돎 | `BUDGET_MAIL=true` 인지, ops 상태의 `skipped_reason` 확인 |

원본 첨부는 **`data/budget_mail/`** 에 그대로 남는다. 파싱이 틀렸을 때 대조할
원본이 없으면 무엇이 틀렸는지 알 방법이 없기 때문이다. 여기 파일을 화면의 기존
업로드 창에 그대로 올려도 같은 결과가 나온다.

## 7. 아직 검증 안 된 것 (실제 메일이 오면 할 일)

정직하게 적어 둔다. 코드는 다음 두 가지를 **실물로 확인하지 못한 상태**다.

1. **실제 IMAP 접속** — 자격증명이 없어 못 돌려봤다. 수집 이후 전 구간(분류 →
   첨부추출 → 파싱 → 대기함 → 등록 → 중복방지)은 가짜 메일로 통과 확인했다.
2. **실제 PDF 명세서** — 메일 명세서는 대개 PDF 인데, 격자선이 아니라 좌표로만 칸이
   나뉘어 있어 지금은 **공백 2칸 이상**을 칸 경계로 추정한다. 그래서 PDF 는 전용
   파서가 아니라 `generic` 이 받고 → **항상 대기함으로 간다.**

실제 명세서가 한 통 오면 `data/budget_mail/` 의 원본을 보고 카드사별 PDF 파서를
붙이는 게 맞다. 그러면 PDF 도 자동 등록 대상이 된다.

## 9. 보안 메모

- `IMAP_PASSWORD` 는 `.env` **평문**으로 들어간다. 이 저장소를 외부에 배포한다면
  메일 비밀번호가 아니라 **앱 비밀번호**(지메일)를 쓰고, 그 계정에 다른 중요한 메일이
  없도록 두는 편이 안전하다.
- 이 기능은 메일을 **읽기만** 한다. 삭제·이동·발송을 하지 않고, 읽음 표시도 바꾸지 않는다.
- 카드사 로그인 정보나 인증서는 쓰지 않는다.
